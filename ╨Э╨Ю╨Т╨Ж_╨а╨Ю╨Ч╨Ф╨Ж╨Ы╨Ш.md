## 🔄 Головне: сумісність зі старими даними

Ви сказали, що в базі інші назви колекцій і полів. Тому замість того щоб
переписувати вашу базу, я зробив **шар сумісності** — `svarog-adapter.js`.

Він читає поле незалежно від того, як воно називається:

| Логічне поле | Розпізнає |
|--------------|-----------|
| дата | `timestamp`, `createdAt`, `created_at`, `date`, `dateCreated`, `time`, `orderDate` |
| імʼя | `name`, `customerName`, `clientName`, `fullName`, `userName` |
| email | `email`, `mail`, `userEmail`, `customerEmail` |
| телефон | `phone`, `tel`, `phoneNumber`, `customerPhone`, `mobile` |
| сума | `totalPrice`, `total`, `sum`, `amount`, `price`, `orderTotal` |
| статус | `status`, `state`, `orderStatus` |
| товари | `items`, `products`, `cart`, `goods`, `positions` |
| місто | `city`, `town`, `settlement`, `npCity` |

Формати дат теж різні — розуміє всі: Firestore Timestamp, секунди, мілісекунди,
ISO-рядок, об'єкт Date. Суму бере навіть із рядка `"3 200 ₴"`.

**Перевірено на трьох різних старих форматах одночасно:**

```
#1  timestamp:{seconds}  totalPrice:2500   → сума=2500  дата=2023-11-14 ✅
#2  createdAt:"ISO"      total:"3 200 ₴"   → сума=3200  дата=2024-03-15 ✅
#3  date:1710000000000   sum:900           → сума=900   дата=2024-03-09 ✅
```

Нічого в базі не переписується — конвертація на льоту при читанні.

### Якщо якесь ваше поле не розпізналось

Відкрийте `svarog-adapter.js`, знайдіть `FIELD_ALIASES` і додайте свою назву
в потрібний масив. Одна строчка — і працює всюди.

### Дізнатись реальні назви полів

F12 → Console:

```javascript
svarogInspectAll()
```

Пройде по всіх колекціях і покаже, які поля є і в скількох відсотків
документів:

```
[SVAROG] Колекція "orders" — 50 документів
  name                  50/50 (100%)
  totalPrice            47/50 (94%)  ⚠️ є не всюди
  createdAt             12/50 (24%)  ⚠️ є не всюди
  timestamp             38/50 (76%)  ⚠️ є не всюди
```

Це одразу показує, чому щось не сходиться.

## 👥 Розділ «Клієнти (CRM)»

Клієнтська база **будується автоматично із замовлень** — зводить їх за email
або телефоном. Працює навіть якщо колекція `customers` порожня. Якщо вона є —
дані доповнюються з неї.

**Сегменти** рахуються самі:

| Сегмент | Умова |
|---------|-------|
| VIP | витратив від 5 000 ₴ |
| Постійний | від 1 500 ₴ або більше одного замовлення |
| Новий | перше замовлення |
| Сплячий | не купував понад 120 днів |

Скасовані замовлення у витрати не рахуються.

Клік по рядку відкриває картку: контакти, метрики, повна історія замовлень.
Є пошук, фільтр за сегментом і експорт у CSV.

## 📈 Розділ «Аналітика»

Періоди: 7 / 30 / 90 днів / рік.

- **Оборот, замовлення, середній чек, % відмов** — із порівнянням до
  попереднього періоду (▲ / ▼ у відсотках)
- **Динаміка продажів** — дві осі: гроші й кількість
- **Топ товарів** — горизонтальні смуги
- **Статуси замовлень** — кільцева діаграма
- **Географія** — таблиця міст
- Експорт звіту в CSV

Усе рахується на клієнті з уже завантажених замовлень — **додаткових запитів
до Firestore не робить**, квоту не витрачає.

## 📣 Розділ «Розсилки»

### Шаблони

Email і SMS. Для SMS — лічильник символів і кількості повідомлень (160/шт).

Змінні вставляються кнопкою: `{name}`, `{email}`, `{orderId}`, `{total}`,
`{status}`, `{ttn}`, `{promocode}`.

Кнопка «Створити стандартні шаблони» додає 4 готові.

### Відправка

Обираєте шаблон і сегмент (VIP / постійні / нові / сплячі / підписники) —
адмінка показує кількість отримувачів і ставить завдання в чергу.

**Ключі Mailgun і Twilio у браузер не потрапляють.** Адмінка лише створює
документ у `campaigns` зі статусом `queued`, а відправку робить Cloud Function
`processCampaign` — пачками по 20 з паузами, щоб не впертись у ліміти.

Правила це підстраховують: створити кампанію можна **тільки** зі статусом
`queued`, вручну поставити «надіслано» неможливо.

Після завершення приходить звіт у Telegram.

### Що налаштувати

Firebase Console → Functions → Environment variables:

```
MAILGUN_API_KEY, MAILGUN_DOMAIN, MAIL_FROM
TWILIO_SID, TWILIO_TOKEN, TWILIO_PHONE
```

Без них розділ працює, але відправка поверне помилку з поясненням.

## 💾 Розділ «Копії та журнал»

### Резервна копія

Кнопка вивантажує **всю базу в один JSON-файл** на ваш комп'ютер.
22 колекції, без платних сервісів. Показує прогрес і що пропущено через права.

### Відновлення

Завантажуєте файл копії → підтверджуєте словом `ВІДНОВИТИ` → база
відновлюється пачками по 400 документів.

⚠️ Документи з тими ж ID перезаписуються.

### Автоматична копія

Cloud Function `scheduledBackup` — щодня о 03:00 за Києвом.
Копії старші 30 днів видаляються самі.

### Журнал дій

Фільтри за адміном, категорією, пошук по тексту. Експорт у CSV.
Читає `admin_logs` і розуміє різні назви полів (`adminEmail` / `admin` / `email`).

## 🚀 Що зробити

### 1. Опублікувати правила (обов'язково)

Додались колекції `templates`, `campaigns`, `backups` — без правил вони
не працюватимуть.

```
Firebase Console → Firestore → Rules → вставити firestore.rules → Publish
```

### 2. Розгорнути Cloud Functions (для розсилок)

```bash
cd functions
npm install
firebase deploy --only functions
```

### 3. Перевірити

Зайдіть в адмінку — у меню з'явиться група «Аналітика та CRM».

```
[ ] Клієнти — список будується із замовлень
[ ] Аналітика — графік показує динаміку
[ ] Розсилки — «Створити стандартні шаблони» працює
[ ] Копії — резервна копія завантажується
```

### 4. Якщо цифри не сходяться

```javascript
svarogInspectAll()    // покаже реальні назви полів
svarogDiagnose()      // покаже помилки доступу
```

Надішліть вивід — доточу адаптер під ваші назви.

## ⚠️ Чесно про обмеження

- **Аналітика рахує тільки завантажені замовлення.** Якщо їх тисячі,
  Firestore віддає не всі одразу — цифри будуть по завантаженій частині.
  За потреби зроблю серверний підрахунок.
- **CRM зводить клієнтів за email або телефоном.** Замовлення без обох
  контактів у базу клієнтів не потрапить.
- **Розсилки не перевірено на живих ключах** — Mailgun і Twilio у мене немає.
  Код відповідає їхнім API, але перший запуск зробіть на одному тестовому
  контакті.
- **Автобекап пише в Firestore**, а не в Google Drive чи S3. Це безкоштовно
  і працює одразу; зовнішні сховища можу додати окремо.
