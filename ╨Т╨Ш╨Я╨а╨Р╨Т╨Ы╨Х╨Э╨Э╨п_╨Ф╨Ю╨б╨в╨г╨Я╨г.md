# 🔧 Статистика, картка та інші дані — виправлено

## Моя помилка в попередніх правилах

Я побудував правила для `config` за **білим списком** — перелічив документи,
які вважав публічними, а решту закрив під `super_admin`.

```javascript
// БУЛО — неправильно
allow read: if docId in ['announcement','contact','shop','heroImages',
                         'pageBackgrounds','combat_report','social',...]
               || isSuperAdmin();
```

Проблеми:

1. **`statistics` у списку не було взагалі** → статистика не завантажувалась
2. **`payment` (реквізити картки) не було** → дані картки не підтягувались
3. **Я написав `social`, а насправді документ називається `socials`** → соцмережі теж відпали

Тобто три розділи я закрив власними руками.

## Як стало

Логіка перевернута: `config` — це налаштування **сайту**, їх за визначенням
має читати кожен відвідувач. Тому тепер закритий тільки справді таємний документ.

```javascript
// СТАЛО — правильно
allow read: if !(docId in ['telegram']) || isSuperAdmin();

allow write: if docId in ['payment', 'telegram']
                ? isSuperAdmin()      // гроші й токен — тільки власник
                : isModerator();      // решту налаштувань — модератор
```

Реальні документи у вашій базі (перевірено по коду):

| Документ | Що містить | Читання | Запис |
|----------|-----------|:-------:|:-----:|
| `statistics` | цифри для сайту | 🌍 всі | модератор |
| `payment` | номер картки, ім'я, банк-URL | 🌍 всі | **super_admin** |
| `socials` | соцмережі | 🌍 всі | модератор |
| `announcement` | банер-оголошення | 🌍 всі | модератор |
| `contact` | контакти | 🌍 всі | модератор |
| `shop` | налаштування магазину | 🌍 всі | модератор |
| `heroImages` | головні банери | 🌍 всі | модератор |
| `pageBackgrounds` | фони сторінок | 🌍 всі | модератор |
| `combat_report` | бойовий звіт | 🌍 всі | модератор |
| `telegram` | **токен бота** | 🔒 super_admin | 🔒 super_admin |

> Реквізити картки публічні свідомо — сайт показує їх відвідувачам для донатів.
> Це не секрет. Секрет — токен бота, він закритий.

## Друга виправлена помилка: список адмінів

Адмінка при старті виконує:

```javascript
db.collection("admins").onSnapshot(...)   // читає ВЕСЬ список
```

Це потрібно, щоб підписувати імена у внутрішньому чаті й у журналі дій.

Моє правило дозволяло читати тільки **свій** запис, а чужі — лише `super_admin`.
Для модератора й оператора цей запит падав і ламав ініціалізацію на старті.

```javascript
// СТАЛО
allow read: if isAdmin() || (isSignedIn() && request.auth.token.email.lower() == email);
```

Читати список колег може будь-який співробітник. Змінювати ролі — як і раніше,
тільки `super_admin`.

## 🧪 Якщо якийсь розділ ще порожній

F12 → Console → команда:

```javascript
svarogDiagnose()
```

Вона покаже точний шлях і код помилки. Три типові відповіді:

**`permission-denied` на конкретній колекції**
→ правило є, але роль не підходить. Перевірте `role` у `admins/{ваш-email}`.

**`failed-precondition`**
→ потрібен індекс, у консолі буде готове посилання на створення.

**Порожньо, помилок немає**
→ значить у самій колекції немає документів. Перевірте в Firestore Console,
скільки там записів. Якщо нуль — проблема на стороні сайту, який туди пише,
а не в адмінці.

## ⚠️ Чого я не можу перевірити звідси

Коду **сайту** в репозиторії немає — тільки адмінка, бот і функції.
Тому я не можу підтвердити:

- чи сайт справді пише в `chats`, `orders`, `feedback`
- чи збігаються назви полів (`timestamp` vs `createdAt`)
- чи не пише він у колекції з іншими назвами

Якщо після публікації правил розділи лишаться порожні, а `svarogDiagnose()`
не покаже помилок — це означає, що дані просто не потрапляють у базу,
і копати треба код сайту. Надішліть його, подивлюсь.
