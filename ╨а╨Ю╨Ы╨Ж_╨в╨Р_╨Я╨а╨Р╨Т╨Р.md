## ⚠️ Дві критичні проблеми, які були у вас

### Проблема 1: ролі не працювали взагалі

Ваша адмінка створює адміністратора так (`admin.html`, рядок 2650):

```javascript
db.collection("admins").doc(email).set({ role: "admin", ... })
```

А старі правила перевіряли зовсім інші назви:

```javascript
function isSuperAdmin() { return getUserRole() == 'super_admin'; }
function isModerator()  { return getUserRole() == 'moderator'; }
function isOperator()   { return getUserRole() == 'operator'; }
```

Роль `"admin"` не збігалась **із жодною** з них. Тому для будь-якого вашого
адміна всі три функції повертали `false`, і працювало тільки читання.

Створити клієнта, змінити статус замовлення, відредагувати новину — усе це
блокувалось на рівні бази.

✅ **Виправлено:** роль `admin` тепер прирівняна до `super_admin`,
тому нічого не зламається. Нові ролі можна вводити поступово.

### Проблема 2: 16 колекцій були заблоковані

У правилах в кінці стоїть:

```javascript
match /{document=**} {
  allow read, write: if false;   // все, що не описано вище — заборонено

```

Описано було лише 9 колекцій. А ваш код звертається до **25**.

Ось що мовчки блокувалось:

## 🛡️ Захист від зловживань

Додано перевірки, яких раніше не було:

**Оператор не може підвищити себе до super_admin**

```javascript
allow update: if isSuperAdmin() ||
                 (request.auth.token.email.lower() == email && keepsLocked(['role']));
```

**Гість не може створити «оплачене» замовлення**

```javascript
allow create: if (isGuest() || isOperator())
                 && request.resource.data.status in ['new', 'pending'];
```

**Гість не може сам схвалити свій відгук**

```javascript
allow create: if ... && request.resource.data.approved == false;
```

**Не можна витягнути всі чати клієнтів**

```javascript
allow get:  if isOperator() || isGuest();   // свій чат за відомим ID
allow list: if isOperator();                // перелік усіх — лише адмінам
```

**Обмеження розміру документів** — `notTooBig(40)` для замовлень,
`notTooBig(15)` для повідомлень і відгуків, щоб ботами не залили базу.

## ⚠️ Одна річ, яку треба змінити на сайті

Правило для відгуків:

```javascript
allow read: if resource.data.approved == true || isModerator();
```

Firestore перевіряє **запит**, а не результат. Тому сайт **зобов'язаний**
явно фільтрувати:

```javascript
// ✅ ПРАЦЮЄ
db.collection('reviews').where('approved', '==', true).get()

// ❌ ВПАДЕ з permission-denied
db.collection('reviews').get()
```

Якщо не хочете правити сайт — скажіть, зроблю читання відгуків повністю
публічним, але тоді чернетки й несхвалені відгуки теж будуть видні.


Якщо десь `permission-denied` — відкрийте консоль браузера (F12),
скопіюйте назву колекції з помилки і надішліть мені, допишу правило.

## 📌 Призначення ролей

Зараз усі ваші адміни мають роль `admin` (= повний доступ). Щоб розділити права,
у Firestore Console змініть поле `role` у `admins/{email}`:

```
admins/manager@svarog.team
  role: "operator"      ← тільки замовлення і клієнти

admins/smm@svarog.team
  role: "moderator"     ← контент і магазин, без ключів оплат

admins/you@svarog.team
  role: "super_admin"   ← повний доступ
```

Змінюйте по одному і перевіряйте — так одразу видно, чи вистачає прав.

> ⚠️ Не знімайте з себе `super_admin`/`admin`, поки не переконались, що
> інший акаунт із повними правами працює. Інакше залишитесь без доступу
> до керування адмінами і доведеться правити роль вручну в консолі Firebase.
