# 🔍 Чому чати, замовлення і форми не підтягуються

---

## Головна причина: помилки були невидимі

У `admin.html` **29 підписок `onSnapshot`** — і в жодної не було обробника помилок:

```javascript
db.collection("chats").onSnapshot(snapshot => { ... });
//                                              ↑
//                        другий аргумент (error) відсутній
```

Firestore при відмові доступу **не кидає виняток** — він мовчки викликає
error-колбек. Якщо колбека немає, помилка зникає безслідно: розділ просто
лишається порожнім, ніби даних немає.

Тому ви бачили пустий екран замість повідомлення «немає доступу».

✅ **Виправлено:** доданий глобальний перехоплювач. Тепер будь-яка відмова
показує зрозумілий текст у вигляді сповіщення і пише деталі в консоль.

---

## Друга причина: замовлення відсіювались сортуванням

```javascript
db.collection("orders").orderBy("timestamp", "desc")
```

Firestore при `orderBy` **виключає з результату документи, у яких цього поля
немає.** Не помилка, не попередження — просто тиша.

Якщо сайт створює замовлення з полем `createdAt` або `date` замість
`timestamp` — список буде порожній, хоча в базі замовлення є.

✅ **Виправлено:** якщо запит із сортуванням повертає порожньо, адмінка
перевіряє колекцію без сортування і, якщо документи там є, перемикається
на читання без `orderBy` і сортує вже на клієнті — з підтримкою
`timestamp`, `createdAt` і `date`.

## 🧪 Як тепер знайти точну причину за 30 секунд

1. Відкрийте адмінку
2. Натисніть **F12** → вкладка **Console**
3. Введіть команду:

```javascript
svarogDiagnose()
```

Отримаєте список усіх проблем із зрозумілим поясненням:

```
[SVAROG] Проблеми з Firestore (2)
  • chats  [permission-denied]
    Немає доступу до "chats". Правила Firestore не дозволяють читання.
    Перевірте, що firestore.rules опубліковані і що ваш email є в колекції admins.

  • orders  [failed-precondition]
    Для "orders" потрібен композитний індекс.
    У консолі нижче буде посилання — відкрийте його і натисніть "Create index".
```

**Надішліть мені цей вивід** — і я скажу точно, що доправити.

## 📋 Що перевірити самостійно

### 1. Правила опубліковані?

```
console.firebase.google.com → Firestore Database → Rules
```

Вгорі має бути свіжа дата публікації. Якщо правила старі — вставте
`firestore.rules` з архіву і натисніть **Publish**.

> Це найчастіша причина. Файл у репозиторії **не діє** сам по собі —
> правила застосовуються тільки після Publish у консолі або
> `firebase deploy --only firestore:rules`.

### 2. Ваш email є в колекції admins?

```
Firestore Database → admins
```

Має бути документ, **ID якого — ваш email у нижньому регістрі**:

```
admins/vladislav@example.com
  role: "admin"        ← або super_admin / moderator / operator
  name: "Владислав"
```

⚠️ Якщо ID документа записаний з великої літери (`Vladislav@...`), правила
його не знайдуть — вони шукають `email.lower()`. Перейменуйте документ.

### 3. Дані взагалі є в базі?

```
Firestore Database → chats     — скільки документів?
Firestore Database → orders    — скільки документів?
Firestore Database → feedback  — скільки документів?
```

Якщо колекція порожня — проблема не в адмінці, а в тому, що сайт туди
нічого не пише. Тоді треба дивитись код сайту (його немає в цьому репозиторії).

### 4. Чи збігаються назви колекцій

Адмінка читає саме ці назви:

```
chats                  ← чати з клієнтами
orders                 ← замовлення
feedback               ← форми зворотного зв'язку
volunteers             ← волонтери
recruiting_applications ← рекрутинг
newsletter_subscribers ← підписники
stock_notifications    ← сповіщення про наявність
```

Якщо сайт пише в `contacts` замість `feedback`, або в `chat` замість `chats` —
адмінка їх не побачить. Перевірте точні назви в Firestore Console.

## 🎯 Найімовірніший сценарій

За моїм досвідом із вашим кодом, порядок імовірності такий:

| # | Причина | Як перевірити |
|---|---------|---------------|
| 1 | Правила не опубліковані | Console → Rules → дата |
| 2 | Email в `admins` з великої літери | Console → admins → ID документа |
| 3 | Назва колекції на сайті інша | Console → список колекцій |
| 4 | Замовлення без поля `timestamp` | Console → orders → відкрити документ |
| 5 | Потрібен композитний індекс | `svarogDiagnose()` покаже посилання |

---

## 🔗 Про композитні індекси

Якщо в `svarogDiagnose()` побачите `failed-precondition` — Firestore сам
згенерує посилання на створення індексу. Виглядає так:

```
https://console.firebase.google.com/project/svarog-team/firestore/indexes?create_composite=...
```

Просто відкрийте його і натисніть **Create index**. Побудова триває
1–5 хвилин, потім розділ запрацює.

## ❓ Що надіслати, якщо не допомогло

1. Вивід `svarogDiagnose()` з консолі
2. Скріншот `Firestore Database` зі списком колекцій і кількістю документів
3. Скріншот одного документа з `orders` (можна затерти персональні дані)
4. Дату публікації правил із вкладки Rules

З цим я скажу причину точно, без здогадок.
