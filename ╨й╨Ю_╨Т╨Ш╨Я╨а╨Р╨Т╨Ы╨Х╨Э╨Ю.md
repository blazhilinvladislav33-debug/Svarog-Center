## 🐛 Чому не створювався реліз

### Причина 1: три workflow воювали між собою

У `.github/workflows/` лежало **три** файли, і всі запускались на push у main:

| Файл | Що робив | Проблема |
|------|----------|----------|
| `build.yml` | збирав .exe/.dmg | завантажував у реліз тільки `if: github.event_name == 'release'` — при push ця умова **ніколи не виконується** |
| `release.yml` | збирав ще раз | створював реліз тільки `if: github.event_name == 'workflow_dispatch'` — при push теж **ніколи** |
| `auto-version.yml` | піднімав версію | створював **порожній реліз без файлів** і робив push, який знову запускав усі workflow |

Результат: файли збирались, лежали в Artifacts, але в Releases не потрапляли ніколи.
А `auto-version.yml` створював порожні релізи — тому в Releases щось з'являлось, але без `.exe` і `.dmg`.

✅ **Виправлено:** три файли видалено, залишився один робочий `build.yml`.

---

### Причина 2: electron-builder не публікував

У `package.json` було:

```json
"dist:win": "electron-builder --win"
"dist:mac": "electron-builder --mac"
```

Без прапорця публікації electron-builder за замовчуванням використовує
`--publish onTagOrDraft` — тобто при звичайному push він просто збирає файл
**і нікуди його не відправляє.**

✅ **Виправлено:**

```json
"dist:win": "electron-builder --win -p always"
"dist:mac": "electron-builder --mac -p always"
```

---

### Причина 3: не було прав на запис

У workflow бракувало блоку `permissions`. Без нього `GITHUB_TOKEN` має
тільки read-доступ, і створення релізу падає з `403 Resource not accessible`.

✅ **Виправлено:** додано `permissions: contents: write`.

---

### Причина 4: не передавався токен у electron-builder

Кроки збірки не мали змінної `GH_TOKEN`, тому electron-builder не міг
авторизуватись на GitHub навіть якби намагався публікувати.

✅ **Виправлено:** додано `env: GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}`.

## 🔄 Чому не працювала перевірка оновлень

Це наслідок Причини 2. `electron-updater` шукає в релізі файли
**`latest.yml`** (Windows) і **`latest-mac.yml`** (macOS) — без них програма
не може дізнатись, яка версія доступна, і показує «помилка перевірки оновлень».

Ці файли генерує **тільки** electron-builder під час публікації (`-p always`).
Реліз, створений вручну через `actions/create-release`, їх не містить —
саме тому оновлення не працювало.

Тепер публікує сам electron-builder → `latest.yml` буде в релізі → авто-оновлення запрацює.

## 🚀 Що робити зараз

### 1. Замініть файли у своєму репозиторії

Розпакуйте архів і замініть:

```
package.json                        ← оновлений
.github/workflows/build.yml         ← оновлений
```

І **обов'язково видаліть** зі свого репо:

```
.github/workflows/release.yml       ← видалити
.github/workflows/auto-version.yml  ← видалити
```

### 2. Перевірте права репозиторію

```
Ваш репо → Settings → Actions → General
→ Workflow permissions
→ ✅ Read and write permissions
→ Save
```

Це потрібно зробити один раз.

### 3. Закомітьте і запуште

```bash
git rm .github/workflows/release.yml .github/workflows/auto-version.yml
git add package.json .github/workflows/build.yml
git commit -m "Fix release pipeline, bump to 3.1.0"
git push origin main
```

### 4. Спостерігайте

```
Ваш репо → Actions → Build and Release
```

```
🟢 build (windows-latest)   ~6-10 хв
🟢 build (macos-latest)     ~8-15 хв
```

### 5. Перевірте Releases

```
Ваш репо → Releases → v3.1.0
```

Має бути **4 файли**:

```
✅ SvarogCommandCenter Setup 3.1.0.exe
✅ SvarogCommandCenter-3.1.0.dmg
✅ latest.yml         ← без нього не працює авто-оновлення Windows
✅ latest-mac.yml     ← без нього не працює авто-оновлення macOS
```

Якщо `latest.yml` є — оновлення в старій програмі запрацює.

## 🔑 Про токен

`GH_TOKEN` у Secrets **більше не потрібен.** Використовується вбудований
`secrets.GITHUB_TOKEN`, який GitHub створює автоматично на кожен запуск
і знищує після нього.

> ⚠️ Персональний токен, який ви раніше надсилали в чат, обов'язково відкличте:
> GitHub → Settings → Developer settings → Personal access tokens → Delete
>
> Токен, що потрапив у переписку, треба вважати скомпрометованим.
